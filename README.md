## Что умеет

- Отвечать на вопросы по 1С с поиском по ИТС и документации платформы.
- Видеть открытый файл, выделенный код и ошибки VS Code.
- Брать в контекст нужные файлы, папки и фрагменты кода.
- Читать, искать, создавать и править файлы проекта. Любое изменение только после вашего подтверждения.
- Проверять синтаксис модулей 1С после правки.
- Работать с git: статус, diff, ревью изменений, коммит, ветки, pull и push.
- Помнить описание и правила проекта (`NAPARNIK.md` и `.rules/`).
- Показывать, насколько заполнен контекст чата, и сжимать длинный разговор, не теряя главного.

## Начало работы

1. Установите расширение: найдите «Напарник» в **Extensions** или выполните
   ```bash
   code --install-extension winst0niuss.naparnik-1c-chat
   ```
2. Откройте Напарника на боковой панели и нажмите «Задать токен». Токен выдают в личном кабинете [code.1c.ai](https://code.1c.ai).
3. Задайте вопрос. Enter отправляет, Shift+Enter переносит строку.

В поле ввода `/` открывает команды, `@` подсказывает файлы и папки проекта.

Нужен VS Code 1.90 или новее.

## Контекст

**Открытый файл** уходит с каждым вопросом: целиком или только выделенный фрагмент, вместе с ошибками VS Code. Какой файл уйдёт, видно на чипе над полем ввода. Клик по чипу отключает его. Если открытый файл уже добавлен в контекст (чипом, папкой или через `@`), второй раз он не отправляется.

Чтобы сразу спросить о выделенном коде, нажмите на нём правой кнопкой и выберите «Спросить Напарника о выделенном коде».

**Файлы, папки и фрагменты** можно добавить:
- в проводнике или на вкладке редактора: правый клик, «Добавить в контекст Напарника»;
- перетаскиванием на поле ввода (если не срабатывает, держите Shift);
- через `@` в тексте вопроса;
- фрагмент кода: выделите строки, правый клик, «Добавить выделенное в контекст Напарника».

Каждый элемент становится чипом над полем ввода. Чипы остаются, пока вы их не уберёте кликом, и у каждого чата свои. Наведите на чип, чтобы увидеть объём. Если приложенное не помещается в лимит, рядом появится предупреждение.

**Лимиты:** до 60 тыс. символов на файл и 150 тыс. на всё вместе. Если папка не помещается, сначала идут описания и файлы верхних уровней, а остальное Напарник дочитает сам, если понадобится для ответа. Без «Доступа к проекту» он может только читать и только внутри этой папки. Файлы, которые не менялись, повторно не отправляются.

## Длинный чат

У модели общий контекст на весь чат, около 262 тыс. токенов. Под полем ввода видно, сколько занято: «Контекст ▰▰▱▱ 32,1% | ⎇ main». Шкала желтеет на 70% и краснеет на 85%, клик по ней сжимает контекст. Справа текущая ветка git, если проект в репозитории.

Когда место кончается, сервис молча забывает начало разговора. Поэтому Напарник сжимает контекст заранее: пересказывает разговор (цель, ваши указания, решения, изменённые файлы, что осталось) и продолжает по пересказу. Пересказ виден в чате как отметка «Контекст сжат», клик по ней его раскрывает.

Сжать вручную можно командой `/compact`. С уточнением, например `/compact решения по регистрам`, Напарник обязательно сохранит указанное. Автоматическое сжатие выключается настройкой `naparnik.autoCompact`.

## Доступ к проекту

Включается кнопкой «Доступ к проекту» над полем ввода или командой `/project`. По умолчанию выключен, запоминается для каждой папки.

С доступом Напарник видит структуру проекта, документацию (README, CLAUDE.md, AGENTS.md и правила других ИИ-инструментов) и ваши правила из `.rules/`. Он сам читает и ищет нужные файлы, а шаги видны в чате.

Правки открываются как diff. Enter применяет, Esc отклоняет, то же можно сделать в карточке в чате. Перенос, копирование и удаление тоже подтверждаются, удалённое уходит в корзину. После правки модуля `.bsl` Напарник проверяет синтаксис и исправляет ошибки.

Всё, что указано в `.gitignore`, Напарник не видит.

## Git

С доступом к проекту Напарник работает с git через встроенное расширение Git VS Code. Просто напишите, что нужно: «что я поменял?», «сделай ревью изменений», «закоммить», «создай ветку feature/x», «отправь в remote».

Когда вопрос касается git, Напарник сам смотрит статус, diff, журнал и список веток. Коммит, создание и смена ветки, pull и push сначала показываются карточкой в чате: Enter выполняет, Esc отклоняет. В коммит входят подготовленные (staged) файлы, а если их нет, то все изменения. Сообщение коммита Напарник пишет в стиле ваших прошлых коммитов.

Напарник делает только то, о чём вы попросили. На «запушь» он не станет коммитить незакоммиченное, а скажет о нём. Отклонённое действие он не повторяет.

Напарник не умеет `reset`, `rebase`, `push --force`, удалять ветки и менять настройки git, а конфликты после pull оставляет вам.

Git работает, если папка проекта в репозитории и вы ей доверяете (не ограниченный режим). Если открыта папка с несколькими репозиториями, а сама она не репозиторий, git недоступен: откройте папку нужного проекта.

## Команды

| Команда | Что делает |
|---------|-----------|
| `/init` | Изучает проект и создаёт `NAPARNIK.md` с его описанием |
| `/rules` | Открывает правила проекта или создаёт новое |
| `/make-rules` | Сохраняет в `.rules/` договорённости из текущего чата |
| `/import` | Переносит правила Claude Code, Codex, Gemini, Cursor, Copilot, Windsurf. Без аргументов показывает, что найдено |
| `/compact` | Сжимает контекст: заменяет историю чата пересказом. Можно уточнить, что сохранить: `/compact решения по проведению` |
| `/clear` | Новый чат |
| `/history` | История чатов |
| `/project` | Включить или выключить доступ к проекту |
| `/stop` | Остановить ответ |
| `/token` | Задать токен |
| `/help` | Все команды |
| `/exit` | Остановить ответ и закрыть панель |

Чтобы добавить правило, напишите «запомни: …». `NAPARNIK.md` и `.rules/` это обычные файлы: их можно править руками и хранить в git, чтобы вся команда работала по одним правилам.

## Настройки

| Настройка | По умолчанию | Что значит |
|-----------|--------------|----------|
| `naparnik.skillName` | `custom` | `custom` ищет по ИТС и документации, `raw` отвечает только моделью |
| `naparnik.timeoutSeconds` | `300` | Сколько секунд ждать ответа сервера. Если сервер завис, выполняя поиск или другой инструмент, Напарник по истечении этого времени попросит модель продолжить |
| `naparnik.autoCompact` | `true` | Сжимать контекст, когда следующий вопрос в него не поместится |
| `naparnik.baseUrl` | `https://code.1c.ai` | Адрес API |
| `naparnik.authFormat` | `plain` | Заголовок Authorization: `plain` или `bearer` |

## Разработка

```bash
npm install
npm test          # unit-тесты, токен не нужен
npm run package   # собрать .vsix
```

Отладка: F5 в VS Code.

## Правовая информация

**Это неофициальный проект.** Он не связан с фирмой «1С», не одобрен и не поддерживается ею. «1С», «1С:Предприятие», «1С:Напарник» являются товарными знаками ООО «1С-Софт» и упоминаются только для того, чтобы указать, с каким сервисом работает расширение.

Для работы нужна своя учётная запись 1С:Напарник. Расширение не обходит ограничения сервиса, а за соблюдение его условий отвечает пользователь.

**Данные.** Токен хранится в защищённом хранилище VS Code (связка ключей ОС). В сервис 1С:Напарник уходят ваши вопросы, открытый файл (если его чип включён), файлы, папки и фрагменты, которые вы добавили в контекст, и файлы приложенных папок, которые Напарник дочитывает для ответа. С включённым доступом к проекту уходят ещё структура проекта и файлы, которые читает Напарник, а при работе с git — статус, diff незакоммиченных изменений и журнал коммитов. Доступ к проекту по умолчанию выключен, а пути из `.gitignore` Напарник не видит. История чатов хранится локально. Телеметрии нет. Запросы идут с заголовком `User-Agent: naparnik-1c-vscode/<версия> (unofficial)`.

**Без гарантий.** Расширение предоставляется «как есть». API сервиса публично не документирован и может измениться. Автор не отвечает за содержание ответов.

Формат API изучен по проектам [1c-ai-mcp](https://github.com/Desko77/1c-ai-mcp) и [spring-mcp-1c-copilot](https://github.com/SteelMorgan/spring-mcp-1c-copilot), подробнее в [NOTICE](NOTICE). Лицензия [MIT](LICENSE).
