# Инструкции для Codex и Claude Code

Общие правила разработки этого репозитория. Codex читает этот файл как проектные инструкции; `CLAUDE.md` подключает его через `@AGENTS.md`. Меняй общие правила здесь, а технические решения и результаты исследований — в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md). Не дублируй их в личной памяти агента.

## Проект

Неофициальное расширение VS Code «Напарник» (`winst0niuss.naparnik-1c-chat`): чат с сервисом 1С:Напарник через недокументированный HTTP/SSE API `code.1c.ai`, без MCP-сервера. Сохраняй формулировку «неофициальный» и оговорки о товарных знаках в README, NOTICE и описании расширения.

## Начало работы

1. Проверь `git status --short` и относящиеся к задаче изменения. Сохраняй чужие правки.
2. Прочитай README и нужные разделы `docs/DEVELOPMENT.md`; ищи через `rg`, не перечитывай весь проект без причины.
3. Сверь команды с `package.json`, типы с `tsconfig.json`, версии зависимостей с `package-lock.json`.
4. Вноси изменения в рамках задачи и выполни подходящие проверки ниже.

## Команды

```bash
npm ci                     # установка по package-lock.json
npm run compile            # TypeScript → out/
npm run watch              # инкрементальная компиляция
npm test                   # компиляция + все unit-тесты, токен не нужен
node --test out/test/protocol.test.js                         # один файл после compile
node --test --test-name-pattern="SEARCH" out/test/*.test.js    # тесты по имени
npm run package            # локальный .vsix; prepublish запускает compile
```

F5 в VS Code открывает окно отладки (`.vscode/launch.json`); предварительная задача компилирует расширение. Линтера и отдельной сборки webview в проекте нет. Правь `src/` и `media/`, а не сгенерированный `out/`.

`npm test` поднимает локальные HTTP-серверы на `127.0.0.1`. Ошибка `listen EPERM` в песочнице требует разрешения на локальный сервер; это не признак регрессии кода. Не удаляй и не пропускай тесты ради обхода этого ограничения.

## Правила изменений

- Читаемость важнее краткости; минимум абстракций, `async/await`, короткие комментарии по-русски. Не делай чисто форматировочные правки вне задачи.
- Для нового или неясного API библиотеки используй Context7: resolve library id → query docs. Для недокументированного API Напарника опирайся на код, тесты и подтверждённые наблюдения из `docs/DEVELOPMENT.md`.
- Сохраняй независимость `src/api/` и чистой логики агентного цикла от `vscode`; окружение передавай через существующие интерфейсы.
- Не заменяй протокол сервиса форматом OpenAI: тело сообщения — `content: { content: { instruction } }`, история связана через `parent_uuid`, SSE читается до конца. События инструментов и heartbeat обрабатываются отдельно от ответа ассистента.
- Команды работы с файлами передаются модели текстом (`@read_file`, `@edit_file` и т. п.). XML сервер может принять за свои вызовы инструментов и обрезать ответ.
- Изменения файлов в самом расширении требуют подтверждения через `EditPreview`; сохраняй привязку к чату, отказ при отмене/закрытии diff и проверку исходного текста перед записью.
- Пути ограничены корнем проекта, включая проверку `realpath`; сохраняй BOM и CRLF файлов 1С. Не добавляй встроенные списки скрываемых папок или файлов: обход учитывает `.gitignore` и `.git`, явное чтение проверяет границы проекта.
- Чтение приложенной папки без доступа к проекту остаётся только чтением внутри этой папки (`FolderReadTools`).
- Git работает через API встроенного `vscode.git`. Сохраняй проверку просьбы пользователя, подтверждение изменений, блокировку повторов после отказа и `postCommitCommand: null` при коммите. Не добавляй неявный push или опасные операции.
- Токен хранится только в SecretStorage, для живых тестов — в переменной окружения `NAPARNIK_API_TOKEN`. Не записывай его в код, инструкции, отчёты или логи.
- В JS-регулярках для русских слов не используй `\b`: он не даёт ожидаемых границ кириллицы.
- Подробности протокола и причины защит описаны в `docs/DEVELOPMENT.md`. Перед изменением соответствующего механизма прочитай его раздел и существующие тесты.

## Проверки

- После изменения TypeScript запускай `npm test`: он включает компиляцию. Для изолированной отладки можно сначала запустить один файл тестов.
- Для `media/chat.js` доступна проверка синтаксиса `node --check media/chat.js`; UI и код, зависящий от `vscode`, проверяй в extension host. Если среда недоступна, явно укажи непроверенное поведение.
- Изменения промптов проверяй также на живой модели, когда есть токен и подходящий проект: моки не подтверждают поведение модели. Команда: `npm run test:live -- --group=api --only=<часть_имени>`; остальные группы и настройки описаны в `src/test-live/run.ts` и `docs/DEVELOPMENT.md`.
- Живые тесты используют внешний сервис. Указывай тестовые проекты явно через `NAPARNIK_TEST_PROJECTS`; не полагайся на личные пути по умолчанию. Тестовые копии создаются в `/tmp/naparnik-test`, исходные проекты не меняются.
- После изменения состава пакета запускай `npm run package` и проверяй архив: `out/extension.js` и ресурсы webview должны быть внутри, инструкции агентов, `docs/`, тесты и локальные настройки — снаружи. `.gitignore` и `.vscodeignore` независимы: проверяй исключения также для личных файлов и вложенных инструкций.
- Не выдавай компиляцию или моки за проверку UI либо живого API. В результате перечисляй выполненные проверки и ограничения.

## Совместная работа

- По умолчанию Claude ведёт фичи, архитектуру и приёмку; Codex — ограниченные задачи ревью, отладки, проверок, локальных фиксов и рефакторинга. Явное назначение задачи пользователем имеет приоритет.
- При передаче задачи укажи цель, границы, критерий готовности, затронутые файлы, уже установленные факты, выполненные проверки и оставшиеся ограничения. Возвращай краткий результат с файлами и проверками.
- Не выполняй повторно завершённую подзадачу без новой причины. Для параллельной работы назначай независимые задачи без пересекающихся правок; число файлов само по себе не повод для субагентов.
- Устойчивые решения храни в документах Git. `ROADMAP.md` в этой рабочей копии — локальные исторические планы, может отставать от кода и не доступен после клонирования. Для передачи задач используй файлы в `docs/` и факты из текущего diff.
- `CLAUDE.md` остаётся короткой точкой входа без копии общих правил. Личные разрешения `.claude/settings.local.json` не переноси в настройки другого агента и не коммить.

## Версии и выпуск

- Повышай версию только по просьбе пользователя, по умолчанию на патч. Синхронизируй `package.json` и `package-lock.json`; изменения выпуска добавляй в верхний раздел `CHANGELOG.md`.
- Локальная сборка `.vsix` не означает разрешение на публикацию. Push, деплой и публикация требуют явного согласия пользователя.
- Marketplace обновляется вручную через страницу управления издателя; скрипты `publish:vscode` и `publish:openvsx` требуют токенов и не являются обычными проверками.
- `vsce package` раньше не находил файлы при слишком длинном пути к проекту; при `Extension entrypoint(s) missing` проверь путь и состав пакета.
- После локальной установки через `code --install-extension naparnik-1c-chat-<версия>.vsix --force` может потребоваться `Developer: Reload Window`. Не повышай версию ради проверки без просьбы пользователя.
- Используй Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `chore:`), без атрибуции ИИ. После изменения кода заверши ответ строкой `Название коммита: <краткое описание в формате conventional commits>`.
